02标准作业流

A. 新场地：SDK 建图（网页「建图录制」组可点着走）

curl -X POST http://192.168.220.8:1448/api/core/slam/v1/mapping/:start   # 停导航栈→起建图栈
# 遥控器慢走全场：<0.5 m/s、缓转弯、玻璃镜面不久留、最后走回起点收回环；起点贴地标！
curl -X POST http://192.168.220.8:1448/api/core/slam/v1/mapping/:finish \
     -H 'Content-Type: application/json' -d '{"map_id":"changdi-1f","name":"场地一层"}'
# 自动：存2D栅格→停栈存点云→打包 .g1map 入库；放弃用 /mapping/:cancel

B. 日常：选图 → 重定位 → 干活

curl -X POST http://192.168.220.8:1448/api/core/slam/v1/maps/changdi-1f/:select   # =启动导航栈
# 把机器人摆到地标（建图起点=地图原点），朝向对齐：
curl -X POST http://192.168.220.8:1448/api/core/slam/v1/localization/:relocalize \
     -H 'Content-Type: application/json' -d '{"x":0,"y":0,"yaw":0}'
curl -s http://192.168.220.8:1448/api/core/slam/v1/localization/pose   # 核对读数

重定位不需要任何安全开关（机器人不动）；但 :select 必须先做——重定位服务是导航 launch 带起来的。

C. 导航与导览

# 导航到点（异步：提交→轮询；坐标采集最准的办法=遥控到位读 pose）
curl -X POST http://192.168.220.8:1448/api/core/motion/v1/actions -H 'Content-Type: application/json' \
     -d '{"action_name":"g1.actions.MoveToAction","options":{"target":{"x":1.0,"y":0.5},"yaw":0,"with_yaw":true}}'
curl http://192.168.220.8:1448/api/core/motion/v1/actions/:current    # 404="空闲"是正常语义
curl -X DELETE http://192.168.220.8:1448/api/core/motion/v1/actions/:current   # 取消

# 导览（航迹点在地图编辑器里点选配置，随地图保存）
curl -X POST http://192.168.220.8:1448/api/tour/v1/tours/:start
curl http://192.168.220.8:1448/api/tour/v1/tours/:current
curl -X POST http://192.168.220.8:1448/api/tour/v1/tours/:stop

C+. 外部动作：回放库（像官方动作一样用）

# 上传录好的双臂轨迹 .npy 入库（frequency 必须=录制频率；query 只能 ASCII）
curl -X POST "http://192.168.220.8:1448/api/core/motion/v1/external-actions?name=pick-cube&frequency=30&velocity_limit=20" \
     --data-binary @real_pick_cube_ep0010.npy -H 'Content-Type: application/octet-stream'

# 列表 / 按 id 执行（同步：响应返回=回放结束）/ 删除
curl http://192.168.220.8:1448/api/core/motion/v1/external-actions
curl -X POST http://192.168.220.8:1448/api/core/motion/v1/external-actions/pick-cube/:execute

前提：终端③执行器在跑。执行期挂 external_motion_running 互锁：官方手臂动作/导航/导览启动都 409，结束自动释放——不会和运控打架（回放走 rt/arm_sdk，腿仍归运控）。首次执行手臂会先移动到轨迹起始位姿，确认周围无人；新轨迹先用小 velocity_limit（如 5）试柔和度。详见上机手册 10 节。

D. 地图编辑器（/sdk/map-editor）

  • 绘制模式：障碍笔画虚拟墙/禁行区、自由笔擦玻璃虚影，1.2s 自动同名保存；只影响规划，不影响定位。
  • 航迹点模式：点击加点、拖动移动；面板配置朝向、TTS、停留、两个容差（到点 reach / 朝向 yaw）、动作序列（机载=手臂/灵巧手；外部=回放库，写 {"executor":"external","type":"replay","id":"pick-cube"}，执行器没起时导览记日志跳过）。
  • 保存并应用：改完一键 重存→重新:select→原位重定位（定位不丢）。

E. 收工

  • 导览在跑先 :stop；依次 Ctrl-C ④③②①（api→执行器→速度桥→roscore）；遥控切阻尼→按官方手册关机。
  • 当天录/改过地图：下载备份 curl -O -J http://192.168.220.8:1448/api/core/slam/v1/maps/{id}/package。

03注意事项

安全红线

① ALLOW_MOTION（不避障速度遥控）只在有人持急停在场时临时开；② 导航前必须处于走跑模式；③ 首次部署不要直接用日常开关组合，按手册分层上电；④ 急停类停止命令永远放行，任何开关都拦不住它——这是设计。

  • 两张网别搞混：192.168.220.8 是对外网（ssh/网页/RViz）；eth0 上的 192.168.123.x 是机器人内网（DDS/雷达），G1_API_MODE_NETWORK_INTERFACE=eth0 和 MID360 配置永远不动。
  • 运动指令单一来源：API 动作执行中别再用 RViz 点 2D Nav Goal（同一个 /move_base_simple/goal，会互相打断且状态机不知情）；RViz 只做观察。
  • 不要手动 roslaunch 导航/建图栈：生命周期归 g1_api（:select / :start / :finish），手动起会两套 FAST-LIO 抢雷达。手动 roslaunch 只留作 g1_api 故障时的兜底调试。
  • 代码同步后要重启 g1_api；改了栅格或 TEB 参数要重新 :select 才加载。
  • 容差不变量：TEB 的 xy_goal_tolerance(0.2) 必须 ≤ 每点的 reach_threshold——反了会"TEB 说到了、g1_api 说没到"死锁到超时（实测教训）。
  • 手臂动作站定做；动作后自动复位(99)+3s 沉降是内置行为。转向注意物理限位 ±1.3 rad，导览点朝向容差建议 ≥0.5。
  • 动作表以真机为准：GET /arm/v1/action-list 现场返回的才是权威（SDK 快照可能滞后，31 号存疑）。
  • TTS：speaker_id 0=中文 / 1=英文（以固件实测为准）；LED 会被本体状态盖掉，用 hold_s 保持。
  • 安全开关改完必须重启服务（启动时读取）；409 时看响应里的互锁名与解法。
  • 地图库已持久化到挂载卷（robot_g1api.sh 内置）——但换机器/重装前仍先下载 .g1map 备份。

动作状态机（思岚语义）

status: 0 NewBorn → 1 Working → 4 Done；终态看 result（0 成功 / −1 失败 / −2 被取消）；空闲查 :current 返回 404 是正常；单槽位，忙时提交 400 ROBOT_BUSY。
